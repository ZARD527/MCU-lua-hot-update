# UART 更新协议

所有多字节整数均采用小端字节序。

## 会话前缀

每次更新会话或独立 RUN 会话都以3个 ASCII 字节开始：

```text
4C 55 41    "LUA"
```

## 数据包头

线上的固定包头长度为6字节：

| 偏移 | 长度 | 字段 |
| ---: | ---: | --- |
| 0 | 1 | 命令 |
| 1 | 1 | 包序号 |
| 2 | 2 | payload 长度 |
| 4 | 2 | payload CRC16 |

CRC16 使用 CRC-16/CCITT-FALSE：初始值 `0xFFFF`，多项式 `0x1021`，不反射，不进行最终异或。空 payload 的 CRC16 为 `0xFFFF`。

## 命令

| 数值 | 名称 | Payload |
| ---: | --- | --- |
| `0x01` | BEGIN | `version:u32, length:u32, crc32:u32` |
| `0x02` | DATA | 1～256字节 Lua 源码 |
| `0x03` | END | 空 |
| `0x04` | RUN | 空 |

BEGIN 从序号0开始。每个成功处理的数据包都会使期望序号递增。独立 RUN 会重新打开一个 `LUA` 会话，并使用序号0。

完整 Lua 源码使用 CRC32/IEEE 校验。允许的脚本最大长度为32 KiB。新脚本版本号必须大于现有有效 Slot 中的版本号。

## ACK/ERR 帧

成功和错误都使用相同的8字节二进制响应帧：

| 偏移 | 长度 | 字段 |
| ---: | ---: | --- |
| 0 | 2 | ASCII `AK` |
| 2 | 1 | 协议版本，目前为 `1` |
| 3 | 1 | 包序号 |
| 4 | 2 | 有符号状态码 `int16` |
| 6 | 2 | 前6字节的 CRC16 |

状态码0表示处理成功。协议层定义的错误码包括：

| 状态码 | 含义 |
| ---: | --- |
| `-100` | 参数无效 |
| `-101` | 包头无效 |
| `-102` | 长度无效 |
| `-103` | CRC16不一致 |
| `-104` | 包序号不符合预期 |
| `-105` | 接收超时 |
| `-106` | 不支持的命令 |

Flash 或更新函数还可能返回其他非零业务错误。收到非零结果后，上位机必须停止当前更新事务；唯一例外是为了恢复丢失的 ACK，而重发与上一个数据包完全相同的包。

## 错误恢复行为

- 等待包头或 payload 超过12秒会终止当前事务。
- 包头非法时会清空待处理接收数据并终止更新。
- 与上一个已处理包完全相同的重复包会收到缓存结果，不会重复执行 Flash 操作。
- 文本日志和二进制 ACK 可以共用输出串口；PC 解析器会搜索有效 `AK` 帧并验证其 CRC16。
